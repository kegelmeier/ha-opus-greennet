# H11 beta verification — 2026-09-30

Environment: Home Assistant 2026.9.4, OPUS-GW firmware 1.21.31,
Mosquitto app 7.1.1. The starting installation was v0.3.3b0, with OPUS
stuck in setup retry. Testing used Home Assistant MCP, SSH, and a direct
gateway test runner. Gateway identifiers, addresses and credentials are omitted.

## Problems found and corrected

- The gateway answers MQTT uptime and device requests but does not answer the
  system-information request required by v0.3.3b0. Health checks now validate
  fresh uptime replies; system information is optional.
- Actual device snapshots contain a list of state descriptors. Discovery now
  reads that format and resolves indexed updates against cached metadata.
  Regression tests cover standalone and embedded channel selectors, and prevent
  cached rocker values from becoming new button events.
- Large retained snapshots with debug logging can exhaust the subscription
  deadline before a health request is sent. Startup probes before subscribing
  to bulk streams, uses a separate subscription deadline, and avoids repetitive
  retained-property debug logging.
- Cover tilt capability did not read the actual `configuration.parameters`
  values in device snapshots. A shutter with `rotationTime=0` incorrectly
  advertised tilt. The parser now uses the reported configuration value instead
  of assuming tilt support from the device profile alone.

## Device checks

| Check | Observed result |
| --- | --- |
| Five Keller lights, individually at 10%, then off | All five returned fresh actuator reports for 10% and 0%. |
| Minimum brightness on one Keller LED dimmer | HA brightness 1 requested; gateway and actuator reported 1%, not off. Restored to 0%. |
| Keller Wohnen shutter, one percentage point only | HA 22% → 23% → 22%; actuator OPUS positions 78 → 77 → 78 confirmed. |
| Other Keller shutter | No movement command; remained HA 18% / OPUS 82%. |
| Entity registry after corrected setup | All 138 existing entity IDs preserved. |
| Restart with original logging configuration | Integration loaded successfully; no manual reload needed. |
| MQTT broker stop/start | Entities became unavailable during the outage and recovered automatically with their original states. |
| Shutters configured with zero rotation time | Both report supported features 15 rather than 143; tilt controls are hidden. |
| Configuration and parameter read services | Both returned successful gateway responses through Home Assistant. |
| Direct HTTP reads | System information and the 65-device snapshot returned HTTP 200. |
| Direct HTTP stream | Parsed initial snapshot and live inbound/outbound telegram frames successfully. |

All five lights were confirmed off after testing. Both shutter positions and
the observed local-control/locking settings matched their baselines. No climate
devices, other-room actuators, full shutter travel or tilt were operated.
The original MQTT bridge file is byte-for-byte unchanged. Temporary logging
overrides were cleared by restart, restoring the configured logging behavior.
An archive of the original integration was kept on H11 for rollback.

Fresh numeric `direction=from` telegrams corroborated the actuator checks;
gateway acknowledgements and optimistic HA states alone were not counted as
success. Dimmers briefly reported `invalid` before reporting a numeric level.
Command-to-valid-report intervals at the gateway were approximately 0.3–1.0 s
for lights and 1.7 s for the one-point shutter movement. These are not UI latency
measurements; the remote MQTT collector itself had delivery delays.
Verbose live-message debug logging can still produce Home Assistant's logging
rate warning during busy traffic; the retained-property startup flood is reduced.

## Scope and limitations

Automated validation: **555 tests pass** on both Home Assistant 2026.8.2 and
2026.9.4, with **90.59% coverage** on 2026.9.4. Ruff lint/format and whitespace
checks pass. Regression tests include real Home Assistant setup, reconnect
ordering, cover capabilities, indexed channel context and cached button events.

Physical light output and shutter mechanics were not visually inspected. Radio
feedback establishes the reported actuator state, not an independent observation
of the attached load. Other EEPs, both channels of a physical multi-channel
actuator, wall-button presses and climate control remain outside this live test.

HTTP reads and streaming worked, but HTTP writes, recovery and feature parity
were not tested. This result supports further API evaluation; it does not
justify replacing the working MQTT transport in this beta.
